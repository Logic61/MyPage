# 山中书斋：第一人称探索

中英文首页共用一个连续的 Three.js 小型山居场景。洞前石径、完整岩穴书斋与东侧木廊可以自由步行；文章、项目、简历仍由现有 Astro 内容系统生成。当前分支在原 3D 原型上重做第一人称操作、近景资产和灯光。

## 使用

- 点击“走进书斋”开始。桌面鼠标锁定后，移动鼠标环顾；不支持锁定时可以按住画面拖动。
- `W A S D` 行走，`Shift` 快走；方向键也可转动视线。
- 看向物件，中央光点出现一圈提示时，按 `E` 或左键交互。拾取射线以眼前第一个实体表面为准，有距离限制，不能隔墙触发。
- 书架打开文章目录，案头手记显示最近文章，工作案打开项目，信笺打开关于与简历。取书等动作先播放，再打开可选择文字的阅读框。
- 庭院纸灯可开关；观景长凳可坐下。坐下后移动或按 `E` 起身。
- `Esc` 暂停并释放鼠标；`M` 打开目录。合上阅读框后，点击“继续探索”恢复鼠标控制。
- 目录中的地点按钮可沿可走路线引导到相应物件；移动或环顾会中止引导。
- 右上回转按钮返回洞口。位置与视线保存在当前会话，浏览器后退恢复也会保留场景。
- 触屏：左侧摇杆行走，右侧拖动环顾，看向物件后轻触交互提示。右上暂停按钮释放操作。
- 暂停页可选择“细致 / 流畅”、视角灵敏度和行走起伏。起伏默认关闭，并遵守系统减少动态效果的偏好。
- 环境声默认关闭，主动开启后才创建音频；页面隐藏时静音。

| `look-controls.ts` | 帧内视角更新、输入源互斥、手动接管、拖动判定与坐姿过渡 |

| `environment.ts` / `environment-geometry.ts` | 连续岩穴、洞口厚度、铺石、木廊、松树、植被、远山、碰撞 |
| `furnishings.ts` / `furnishing-ink.ts` | 线装书、桌案榫接、笔墨、茶盏、浑天仪、信笺、灯笼、中文图集与动画 |
| `lighting.ts` | 日光、洞口天光、室内面光与程序 HDR 天空 |

| `ui.ts` | 目录搜索、同源正文读取、请求取消、焦点、图形不可用时的阅读入口 |

所有场景资源由代码、CPU 数据纹理或本地 Canvas 文字图集生成，不依赖模型 CDN。石材使用多尺度层理、裂隙、法线和粗糙度；木材、纸张、布、黄铜与陶瓷各有独立的表面响应。静态几何按材质合并或实例化。洞顶常驻，不再切开或淡出。

站立地面为 `y=0.3`，眼睛为 `y=1.98`；桌面为 `y=1.08`。坐姿的 `sitPosition` 指座面接触点，相机另外加 `.8m`。目前通行区是同一高度的山腰台地；通往山下的石阶有可见绳栏，属于景观。扩展高差探索时，需要同时实现地面高度查询与导航，不能只修改可见网格。

灯光使用真实方向光、面光、灯具点光与环境反射。室内面光用于美术控制的反弹光近似；当前没有烘焙光照图、实时全局光照或光线追踪。细致档开启 GTAO 和少量辉光，流畅档关闭这两项。分辨率受像素预算约束，持续慢帧时会逐级降低；这不构成任何设备的帧率保证。

## 视角与输入

鼠标事件只累积目标角度，由动画帧统一更新实际朝向。手动环顾采用 12ms 时间常数的短平滑，不把像素位移乘帧时间，不限制正常快速转身的总角度。桌面拖动与锁定使用同一灵敏度系数；触屏保留独立系数。暂停、阅读或失去鼠标锁定会清除尚未显示的输入，重新进入后不会继续追赶旧视角。只有锁定切换后的第一个短时大位移样本受到回中防护，正常连续输入没有速度裁剪。

任何有效的非零手动环顾都会中止导航和自动朝向。导航抵达、坐下时使用最短弧的有界转向；坐下和起身的位置在 0.3 秒内过渡（减少动态效果模式为 0.15 秒，且坐下不强制转身）。起身回到坐下前的安全站位。姿态过渡只影响相机偏移，正常行走仍直接跟随碰撞计算结果。拖动手势从按下位置累计判断，慢拖和拖回起点不会被误当成点击。

优先请求 `unadjustedMovement`；只有明确的 `NotSupportedError` 才尝试一次普通锁定请求，其余失败使用拖动模式。Promise 版本的错误按 rejection 分类，旧版无 Promise 的接口等待锁定事件；连续请求、迟到的错误与模式切换分别处理。参见 [MDN Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)。

交互检测先求可交互物的精确命中，再检查最近目标前的遮挡。较大的普通三角形网格按保守包围盒排除不相关区块，最终命中仍使用 Three.js 的原始三角形、材质和正反面规则；实例、骨骼及自定义 raycast 保留原流程。渲染尺寸未改变时不会重新分配绘图缓冲，GTAO 也只在实际尺寸变化时调整一次。

## 开发与验证

需要 Node.js 22.12 或更新版本。

```sh
npm ci
npm run dev
npm run check:world
npm run test:world
npm run build
```

导航测试覆盖绕障、身体与地图边缘间隙、长步长穿墙、门洞连通及不可达目标。第一人称测试覆盖实体遮挡、隐藏父节点、雾与玻璃、交互距离、背对物件以及斜向行走速度。

输入回放测试覆盖 30/60/144/240Hz 帧率与不同鼠标采样率下的转向距离、快速大角度转身、连续 1px 慢拖、暂停恢复、锁定/拖动切换、过期输入、最短弧自动转向、手动接管及连续坐下/起身。锁鼠兼容测试覆盖 Promise 和事件的顺序、原始输入不支持、权限失败、重复请求及已取消请求的迟到结果。这些是逻辑回放，不等同于真实设备的输入延迟或 GPU 帧率测试。

视角修复时，用同一 Node 进程里的实际场景交替比较旧、新拾取实现。900 条转头射线及 120 条家具动画射线的交互结果全部一致；另以旧实现核对了 157 组几何边界。以下是本次 CPU 求交耗时，受测试机器影响，不能直接换算成网页帧率：

| CPU 检测场景 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 转头射线平均耗时 | 3.370ms | 0.049ms |
| 近书架瞄准中位耗时 | 4.135ms | 0.480ms |
| 近书架瞄准 P95 | 7.126ms | 0.819ms |

较大网格的区块索引在进入探索前准备，本次约 38.9ms。动态顶点或索引应通过 `needsUpdate` 更新版本以使缓存重建；未来新增返回其他对象命中的自定义 raycast 时，需要重新检验目标分类语义。

场景整合检查六处实际交互点的可达性及眼高射线命中、屋顶连续性、几何有限值和生命周期；材质 shader 经过离线 Mesa EGL 的编译与链接检查。离线画面检查从实际 Three.js 资产导出到 Blender，以核对构图、比例、法线、纹理与遮挡，不是浏览器运行截图，也不包含浏览器后处理效果。

测试浏览器禁用 WebGL，实际网页中可验证目录、搜索、正文及公式阅读、返回和无三维能力时的入口。完整实时画面、设备帧率、鼠标锁定与触屏手感仍需要支持 WebGL2 的浏览器验收。
