# 云庭书斋：第一人称山居

中英文首页共用一个连续的 Three.js 小型山居场景。当前版本以明亮的仙山庭院为中心：三面屋宇围合露天天井，北厅保留主案与山水圆屏，两翼分别安置藏书和观物空间，东廊通向云海露台。文章、项目和简历继续使用现有 Astro 内容系统，场景物件提供进入内容的路径。

## 空间与材质

### U 形平面

以世界坐标的负 Z 方向为北。从南侧庭门进入，沿石径经过水庭，向北看见主案后的圆屏。主要行走空间、屋面下的停留空间和远景应能从第一人称视角分辨。

| 场所 | 空间职责 |
| --- | --- |
| 北厅「云庭书斋」 | 主案、案头手记和信笺的阅读空间；保留原山水圆屏作为背墙焦点 |
| 西翼「藏书小阁」 | 藏书架沿西侧布置，朝向庭院；留出取书和近看书脊的站位 |
| 东翼「临庭观物」 | 工作案与浑天仪朝向内庭，承接项目入口 |
| 「天光水庭」 | 中央露天天井与入庭路径；水庭偏西，东侧保留向北厅行走的清楚通道 |
| 「临云长廊」 | 东侧半室外廊道，连接屋宇与露台，通过立柱和开口组织远景 |
| 「松间露台」 | 面向云海的停留区域，保留观景长凳 |
| 「云山石径」 | 南门外及其他室外通行区域，衔接山居与周围自然环境 |

区域边界由 `main.ts` 的 `describePlace()` 判断；可走范围与实体碰撞由环境和家具模块提供。修改布局时应一起更新这些定义。北厅和两翼使用室内声场，天井、长廊与露台保留室外声场。

### 材质分工

| 材质 | 主要用途与设计约束 |
| --- | --- |
| 白灰泥 | 墙体和室内背景，承接天光与窗影，保持大面的安静和明亮 |
| 浅木 | 室内地板、廊面、窗洞内侧及檐下顶面，保持明亮且能读出板材铺向 |
| 深木 | 梁柱、稀疏格栅、主案和藏书架，交代构造与人体尺度，衬托白墙和画面 |
| 净石 | 通行地面、门槛、池沿和台地基座，以清楚的块面与接缝组织路径 |
| 深青屋面 | 标明北厅和两翼的屋顶轮廓，形成檐下阴影，与露天天井区分 |
| 纸、绢、布、黄铜与陶瓷 | 服务书籍、圆屏、灯具、器物和软垫的近看细节 |

材质的颜色、粗糙度、法线和纹理尺度各有职责。白墙不铺满碎石噪声，浅木不与深青屋面混成一整片暗色；水庭和天井保留开敞的天光，圆屏仍是可阅读的画面。

### 实现与评审参考

以下为本轮查阅的一手文档和源码，用于约束材质、空间呈现与验证方式。具体图片的来源仍以资产记录为准。

- [Felix Rieseberg：Made by mechanical means](https://felixrieseberg.com/made-by-mechanical-means/)：介绍真实房间结构与窗外图片、深度信息结合的做法。本项目采用近景几何与远景图片的分工；该实例中的烘焙光照图与图像深度估计并未在本项目实现。

## 使用

- 点击「走进云庭」开始。`W A S D` 行走，`Shift` 快走，方向键转动视线。
- 桌面锁鼠成功后，系统光标隐藏，移动鼠标环顾；用中心准心瞄准物件，按 `E` 或左键交互。
- 未锁定时，按住画面拖动环顾，用实际鼠标指向、点击物件；`E` 使用同一个鼠标目标。右上「锁定鼠标」可主动重试，等待期间不触发物件。
- 藏书架打开文章目录，案头手记显示最近文章，工作案打开项目，信笺打开关于与简历。取书等动作先播放，再打开可选择文字的阅读框。
- 纸灯可以开关，观景长凳可以坐下；坐下后移动或按 `E` 起身。
- `Esc` 暂停并释放鼠标，`M` 打开目录。合上阅读框后，点击「继续探索」恢复控制。
- 目录地点按钮沿可走路线引导至物件；有效的手动环顾或行走会中止引导。右上回转按钮返回庭门。
- 触屏使用左侧摇杆行走、右侧拖动环顾，看向物件后轻触提示。当前输入按实际指针类型切换，触屏设备接鼠标也能使用鼠标模式。
- 暂停页可选择画面档位、灵敏度和行走起伏。起伏默认关闭，并遵守系统减少动态效果的偏好。
- 环境声默认关闭，主动开启后才创建音频；页面隐藏时静音。

### 瞄准与输入合同

实际 `document.pointerLockElement` 决定是否锁鼠；页面处于探索状态不代表锁鼠成功。

| `data-input-mode` | 可见反馈与交互目标 |
| --- | --- |
| `locked` | 系统光标隐藏，中心准心与中心射线一致 |
| `pointer` | 保留系统鼠标，不显示中心准心；按画布 CSS 范围换算鼠标射线，物件提示跟随鼠标 |
| `drag` | 累计手势达到拖动阈值后，暂时隐藏鼠标并使用中心准心；松开不触发点击 |
| `touch` | 使用中心瞄准及触屏交互提示 |
| `pending` / `none` | 不进行物件瞄准或交互 |

鼠标离开画布时清空悬停目标。拖动从按下位置累计判断，连续小位移或拖回起点都不能被误当作点击。拾取先取得可交互物件的精确命中，再检查目标前的实体遮挡和距离，不能隔墙触发。

鼠标事件累积目标角度，动画帧统一更新显示朝向；像素位移不乘帧时间。手动环顾使用短时间平滑，暂停、阅读或失锁时清掉尚未显示的旧输入。导航抵达和坐下采用最短弧的有界转向，手动输入可以立即接管。坐下与起身使用位置过渡，起身返回之前的安全站位。

优先请求 `unadjustedMovement`，仅明确的 `NotSupportedError` 允许一次普通锁定请求；其他失败进入可拖动环顾的指针模式。Promise 接口按拒绝原因分类，旧版接口等待锁定事件。取消的旧结果不能改变当前模式；明确的新进入操作可以承接仍待决的唯一请求，避免同时排队多个原生请求。实现与兼容说明见 `pointer-lock.ts` 和 [MDN Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)。

建筑、家具和近景地形采用代码构造的真实几何，基础表面结合 CPU 纹理与 Canvas 文字图集。静态几何按材质合并或实例化。两张主要画面资产是已生成并随站点打包的本地图片：

- `mountain-silk-landscape.webp`：保留的圆屏山水绢画，使用普通 sRGB 漫反射贴图；画面不自发光。

图片的生成方式、实际尺寸、提示词、无损 WebP 转换及投影方式见 [public/world/README.md](../public/world/README.md)。圆屏画与远山图是两个独立资产；维护时不要将其用途或来源混为一项。

## 加载、渲染与释放

环境的可走面、collider、交互物件和背景 fallback 几何同步创建。图片的异步就绪只替换贴图，不能在导航或拾取器建立之后悄悄增加新的关键结构。

画作的 `assetsReady` 与背景的 `ready` 共用一次 **1500 ms** 有界等待。全部完成则提前编译场景；失败或超时后，圆屏的 Canvas 山水和背景的同步几何与渐变天空允许继续进入。迟到的图片仍可以正常替换，已经释放的场景则丢弃并释放迟到纹理。

从 renderer 创建起便注册幂等 `teardown`，覆盖初始 RAF、字体、图片和编译阶段。退出时清理等待 timer、结束当前初始化等待并释放已创建资源；等待结束后先检查页面和资源状态，再启动编译。编译过程中离开，后续结果不会再次渲染或启用界面。图形上下文丢失也终止初始化并显示真实阅读入口。BFCache 暂存走暂停与恢复流程，保留当前文档所需的资源。

背景必须先于渲染管线创建，其根节点带有 `ignoreAmbientOcclusion` 标记。AO 通道临时隐藏整棵背景与粒子、线条等排除对象，并通过 `finally` 恢复原有可见性。后处理抛错时，先恢复临时覆盖材质、自动清屏开关、清屏颜色与透明度，再切回直接渲染，避免把法线通道的状态带入正常画面。

新增可选图片时，应接入现有共同等待和清理队列，并提供同步 fallback。若异步加载的是建筑或关键碰撞结构，则必须先完成结构加载再创建导航与拾取器，不能直接沿用装饰图片的超时放行方式。

## 坐标、导航与状态恢复

主通行面固定为 `y=0.3`，站立眼睛为 `y=1.98`，相对地面眼高为 `1.68 m`。导航只处理 `x/z` 单层平面。可见台阶或坡面不会自动改变人物脚底高度；扩展高差探索时，需要一起实现地面高度查询、身体移动与导航。

`sitPosition` 表示实际座面接触点，相机另加 `.8 m`。家具调整位置或朝向时，必须同步更新 mesh、物件瞄准中心、`approach`、collider 和坐姿数据。六个交互 ID 保持为 `books`、`latest`、`projects`、`about`、`lantern`、`bench`，实际坐标以家具模块为准。

当前入口为 `(x=1.3,z=11)`，`#study` 返回落点为 `(0,-4.6)`。出生点与候选落点都要通过 `canWalk` 验证；没有安全出生点时显示阅读回退，不把人物放到未经检查的旧坐标。`#study` 是独立文章页「回到书斋」的公开链接，应在改版时继续支持。

会话位置键为 `mountain-first-person-v3-cloud-court:${base}`。中英文共享同一布局位置；有效存档优先于 `#study`，恢复前检查可站立性。存档记录站位与视线，坐下时保存原站位。重大布局变更应升级地图版本，避免把旧坐标和旧朝向沿用到新建筑；画面质量与灵敏度偏好独立保存。

改布局的最小同步范围是：入口与返回落点、区域名称与室内判断、可走面和障碍、六处交互及坐姿、灯光位置和阴影范围、真实场景 QA 机位。`findPath()` 会调整不安全的目标点，因此验收时还必须单独确认每个原始 `approach` 可站立。

## 开发与验证

需要 Node.js 22.12 或更新版本。

```sh
npm ci
npm run dev
npm run check:world
npm run test:world
npm run build
```

本轮恢复后已实际执行 `check:world`，严格 TypeScript 检查通过；`test:world` **69 项通过**。其中恢复原有 68 项逻辑回归，并新增一项后处理异常状态恢复回归，覆盖以下范围：

- 导航绕障、身体间隙、地图边缘、长步长穿墙、门洞与不可达目标。
- 精确拾取、遮挡、隐藏对象、材质透明度、交互距离和方向移动。
- 不同帧率与鼠标采样率的视角回放、连续小位移拖动、锁定与拖动切换、旧输入清理、自动转向、手动接管和姿态过渡。
- 锁鼠请求的 Promise/事件顺序、原始输入不支持、权限错误、重复请求、取消与重新进入。
- 真实主入口代码的模拟 DOM 事件与 Three.js CPU 射线：鼠标目标一致性、阅读返回、失焦、迟到锁定、混合输入、资源共同等待、超时、退出及上下文丢失。
- 新布局存档版本、`#study` 落点、非法出生点的回退、三个屋翼与室外区域的归属。
- 调用已安装 GTAOPass 的真实材质覆盖方法并注入渲染异常，确认背景和粒子可见性、材质及清屏状态在直接渲染前恢复，原本隐藏的对象仍保持隐藏。

完整 Astro 构建通过，输出 **296 个页面**。针对真实环境、家具与碰撞数据另做了 CPU 整合检查：六处原始交互接近点均可安全站立并从庭门抵达，路径终点没有被调整；每处中心及八个邻近偏转射线均正确命中，共 **54/54**。十四个主要位置连通，南门、东翼侧门和前庭东出口的眼高通道畅通；中庭露天、三个屋翼有顶，水庭首命中为水面，入口走道和边带同层。

圆屏和远山实际图片均成功加载，远景模块的加载失败、幂等释放与销毁后迟到结果也通过定向检查。主入口的坐下/起身、锁鼠和阅读返回由事件回放覆盖；上述检查不代表在真实 GPU 或原生输入设备上验收。

离线画面检查从实际 Three.js 几何、纹理和灯光导出到 Blender；最终以入口、内庭、露台三个固定机位复核构图、比例、贴图与遮挡。世界三向投影材质还原颜色和 ORM，近景凹凸在离线检查中用几何法线近似。远山高度已按这张生成图的实际山脊校准，松冠使用分散的针叶束，保留枝间天空。离线渲染不是浏览器截图，光照计算也与网页不同，不能代替 WebGL 后处理、原生锁鼠、触屏手感或 GPU 性能验收。CPU 求交耗时不能直接换算为网页帧率；场景变化后需要重新测量，旧布局的性能表不作为当前版本结论。

完整实时画面和设备表现仍须在支持 WebGL2 的浏览器中检查；目录、搜索、正文与公式、返回及无三维能力时的阅读入口需分别验证。灯光中的面光是受控的反弹光近似，当前没有烘焙光照图、实时全局光照、光线追踪或图片深度估计；质量档位和动态分辨率也不构成任何设备的帧率保证。
